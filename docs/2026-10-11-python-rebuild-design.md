# TokenView Python 重构设计稿

日期：2026-10-11  
状态：用户要求连续执行，已进入实现并完成本机运行验收；AGY 多账号仍受通道限制  
目标目录：`D:\myagent\TokenView-Python`  

## 1. 目标与边界

以独立 Python 桌面程序重做 TokenView，供用户本人日常使用和真机核验。V1、V2、V3、V4 的目录、源码与既有备份均保持原样，不覆盖、不删除；新版本单独开发。现阶段提供可直接运行的 Python 预览，不编译、不打包，直到用户确认。

本设计中的“恢复功能”指恢复到已确认的个人版范围，而非把商业版全部模型、许可证、Pro 限制或未经验证的演示数据搬入新程序。

首版只包含：

- Codex 订阅：使用用户授权的 Codex 登录态，展示官方查询通道实际返回的额度。
- Google Antigravity：调用本机 AGY CLI 的只读 `/usage` 查询；不得把 AGY CLI 描述为 Google 官方 CLI。
- DeepSeek API：用户添加一个或多个 API Key，使用 DeepSeek 官方余额通道查询。
- MyAgents 吸附模式：仅当 MyAgents 主窗口处于前台时显示胶囊；展开后显示完整窗口，关闭/收起行为不产生脱离宿主的空壳窗口。
- 多账号：Codex、Antigravity 和 DeepSeek 均按账号/配置行管理；DeepSeek 行对应独立 Key。列表和胶囊明确标识当前账号，切换账号不应重置模型选择或窗口状态。
- 默认每 5 分钟刷新，可在设置中调整；支持手动刷新、低额度提醒、上次更新时间、缓存/过期状态、错误状态和空授权状态。
- 设置仅保留：开机启动、额度提醒、刷新间隔、胶囊尺寸。尺寸选择后点“应用”立即生效，设置页保持打开。
- Codex Tibo：如版本2基线存在且来源仍可访问，抓取 `codex-reset.com` 最新第一条原文，不翻译，并提供原文来源链接；抓取失败时显示错误/旧缓存，不造内容。
- 本地数据和隐私说明、删除账号/Key/本地数据入口、最小化诊断日志。

明确不做：许可认证、商业 Pro 门槛、付费/发卡、商业多模型目录、网页 Cookie 抓取、非公开额度接口、虚构样例额度、后台上传账号信息，以及本轮未经用户确认的安装包或编译产物。

## 2. 交互与视觉行为

### 2.1 胶囊

- 胶囊贴合 MyAgents 主窗口的既定位置，只在宿主有效时显示；宿主隐藏、关闭或重启期间不显示孤立窗口。
- 默认宽度按内容自适应，不保留无意义空白；内容只显示当前模型/账号名称及两个最重要指标。
- Codex 和 Antigravity 有 5 小时、周额度时按 `5H 百分比`、`周 百分比`显示；未返回的指标显示状态占位而非推算值。DeepSeek 展示余额和赠送余额（若接口实际返回）。
- 主题色用于图标、选中态和进度条。模型切换后胶囊应跟随所选模型；切账号时保持模型不跳回首项。
- 点胶囊可展开；展开窗口根据内容和可用工作区自适应，不能被胶囊的窄宽度、屏幕边缘或裁剪区域挤压。可拖动/定位规则沿用版本2中已确认的行为，细节在实现前通过现存源码核对。
- Pin 图标保持低调的主题色风格，鼠标悬停提供“固定窗口”/“取消固定”说明。

### 2.2 展开面板

- 顶部模型切换；选中模型下列出该模型的所有账号，一账号一行。
- Codex/Antigravity 行：账号名称、5H 和周额度，各自显示百分比、进度条及官方返回的重置时间；不提供的字段不补猜测值。
- DeepSeek 行：账号/Key 标签、余额、赠送余额（官方响应可得时）及刷新状态；Key 明文永不显示。
- 刷新、设置、收起操作位置紧凑；不重复展示缩略胶囊已有的无关字段。
- 数据错误时保留最近成功快照并清楚标为“上次成功时间/数据已过期”，不能把旧值伪装成刚查询的数据。

## 3. 技术方案

### 3.1 技术选择

- 业务逻辑、界面和宿主控制代码均用 Python 编写。
- 使用本机已验证可导入的 Python.NET + Windows Forms + System.Drawing，采用原生窗口和自绘控件。不使用 HTML/WebView、Rust/Tauri 或 PyQt；避免旧版打包体积和 WebView 窄视口裁剪问题。
- Win32 集成通过 Python `ctypes` 封装，集中处理宿主进程/窗口探测、窗口定位、DPI、透明/圆角裁剪和前后台状态。只在真机实测通过后才承诺具体的吸附/透明效果。
- 直接运行入口为 `pythonw.exe` 启动 `.py`，控制台错误写本地滚动日志；开发期可提供命令行诊断入口。安装器/EXE/ZIP 暂不生成。

### 3.2 模块边界

- `app/`：应用启动、单实例、退出和恢复。
- `ui/`：胶囊、展开面板、设置页、账号行、自绘进度条、主题与状态提示。
- `host/`：MyAgents 窗口检测、吸附定位、DPI/多屏、激活与隐藏策略。
- `providers/codex/`：执行固定只读 App Server 额度查询；按账号配置隔离官方 CLI 登录上下文；不直接显示或复制令牌。
- `providers/antigravity/`：调用固定 AGY CLI `/usage` 只读命令，解析可验证字段；限制超时和输出大小。
- `providers/deepseek/`：固定官方余额主机的只读请求，Key 仅从加密存储短暂读取到进程内。
- `services/`：调度、缓存、告警、Tibo 最新信息抓取、账号切换和状态聚合。
- `storage/`：设置、账号元数据、缓存和加密秘密的本地持久化。
- `tests/`：Provider Fixture/契约测试、状态与调度测试、WinForms/Win32 集成测试和运行检查。

Provider 共用统一接口：`refresh(account) -> QuotaSnapshot`。快照含产品、账号 ID、字段及来源、采样时间、重置时间、成功/失败状态和错误类别。UI 不调用 Provider；所有结果先经过状态/缓存层，过期状态保留可追溯时间戳。

### 3.3 账号与凭据

- Codex：通过官方 Codex 登录流程授权。每个账号必须有独立、明确的登录配置上下文；禁止复制令牌文件或暗中复用 MyAgents 自身会话。移除账号后清理本程序创建的上下文和缓存，但不得擅自删除用户已有的官方 CLI 数据。
- Antigravity：目前已知 AGY `/usage` 读取当前登录账户。多账号需要验证 AGY 是否有受支持的独立配置根/账户切换机制。只有存在可维护、可隔离且不读取 Cookie/私钥文件的路径时才实现多账号；否则保留接口和清晰的单账号限制说明，并将“AGY 多账号”标为未解决，而不是冒充已完成。不得采用抓取私有 API、逆向 OAuth 客户端或复制第三方 Token 的捷径。
- DeepSeek：支持添加多个 Key；账号标签由用户填写。通过 Windows DPAPI（用户范围）加密保存，网络仅访问固定官方余额端点，日志屏蔽 Key。移除 Key 后清理与之关联的缓存。
- Codex/AGY 登录由官方 CLI/授权窗口完成；TokenView 只执行明确说明的只读查询命令/RPC，不读取浏览器 Cookie，不向服务端上传凭据。

## 4. 刷新、缓存、告警与失败处理

- 单一后台调度器按用户设定间隔执行；默认 300 秒。一次失败不阻塞其他账号或模型；同一账号避免重入。
- 运行时缓存最近成功的字段和时间戳；程序重启后可恢复展示最后成功值并标记旧数据。手动刷新与周期刷新使用相同路径。
- 指标只呈现来源真实返回值，缺项显示“不可用/未返回”；禁止从额度、用量或窗口时间推算不存在的指标。
- 错误分为未登录、CLI 缺失、超时、网络、鉴权拒绝、响应格式变化、接口限流和未知错误；UI 用简短中文，诊断日志保留错误类别，不记录凭据/完整敏感响应。
- 低额度阈值与提醒频率需以版本2既有行为核对后继承；若旧实现未清楚定义，首版采用可配置阈值及同一窗口周期内仅提醒一次，避免频繁打扰。
- 离线期间不连续弹窗；恢复联网后只在成功刷新且跨过阈值时触发一次提醒。

## 5. Tibo 信息抓取

- 固定站点 `https://codex-reset.com/`，抓取 tracker/信息流中最新的第一条记录，保留原文，不翻译。
- 使用页面结构化数据或稳定 DOM 解析；不得把任意页面文本错误识别成帖子。存来源 URL、发布时间、抓取时间和原文摘要。
- 定期抓取失败时显示最近成功项和“抓取失败/内容可能过期”，提供 Open source；链接使用完整绝对 HTTPS URL。
- 页面结构变化有契约测试/解析器失败状态；不绕过登录、反爬或访问控制。

## 6. 数据、安全和生命周期

- 账户标签、偏好、最后成功快照存于程序自己的 `app-data`；密钥/授权信息优先留在官方 CLI 自己的授权存储中，DeepSeek Key 使用当前 Windows 用户 DPAPI 加密。
- 不采集遥测，不上传快照，不保存明文 API Key；诊断日志有大小上限和轮转。
- 退出后停止定时器、子进程和网络请求；禁止程序关闭/杀死 MyAgents。CLI 调用使用固定可执行文件及参数、超时、受限输出；不从账号输入拼接 shell 命令。
- 自动启动通过当前用户启动项，设置页可关闭并移除本程序注册项。运行不依赖管理员权限。
- 单实例可将第二次启动转为唤醒现有窗口，不另起覆盖进程。

## 7. 风险与先行可行性门槛

1. **AGY 多账号隔离（首要门槛）**：只用 AGY 支持的配置/登录能力做隔离实验；不动现有账号数据、不复制 Token。实际空 USERPROFILE/APPDATA/配置目录仍使用共享登录，因此当前交付明确仅支持当前一个账号；独立多账号未实现，不能称全部需求完成。
2. **Codex 多账号授权体验**：确认官方 CLI 可在独立数据根里完成独立登录及 App Server 查询；验证不会改变用户日常 Codex 登录态。
3. **WinForms 视觉与宿主吸附**：先做窄范围桌面运行验证。自绘透明、DPI、点击穿透/命中、贴边以及宿主重启需要分别测；普通单屏截图不能代表多屏验收。
4. **Tibo 页面稳定性**：确认站点实际 DOM/结构后再定解析方式，避免基于旧截图猜结构。
5. **Python.NET 运行条件**：本机 Python.NET/WinForms 已通过导入级验证；干净机器的运行时依赖暂不承诺，待本机源码预览稳定后另行决策。任何后来打包均须用户确认。

如果任一登录隔离门槛不可实现，则对应模型不能声称“多账号完整可用”；不得改用未公开端点、Cookie 抓取或假数据掩盖。

## 8. 验收标准

### 数据正确性

- 使用用户提供的真实授权/Key，在用户同意的本机环境逐账号核对官方 CLI/页面或 API 响应，记录查询时间、原始字段含义、TokenView 展示值和差异；未实测的账号只显示未验证状态。
- Codex 与 AGY 的 5H/周字段映射和重置时间与原始返回一致；DeepSeek 余额字段及单位与官方返回一致。
- 所有测试 Fixture 明确标为测试，不进入可见生产数据路径。

### UI 与窗口

- 直接通过 Python 运行可预览，无打包；默认胶囊紧凑自适应，展开后完整宽度/高度可读，不出现之前 V4 的外围矩形阴影或内容挤压。
- 模型和子账号切换后选中态、列表、胶囊保持一致，不跳回 Codex。
- 设置页“应用尺寸”立即改变胶囊且不退出设置；5 分钟默认刷新、手动刷新、关闭自动启动/提醒均有可观察结果。
- MyAgents 不可用期间没有孤立悬浮窗；重新出现时可恢复。不能因关闭 TokenView 关闭 MyAgents。

### 稳定性与数据边界

- 模拟离线、命令超时、登录失效、错误 JSON、多个账号中部分失败、睡眠恢复、Explorer 重启时不崩溃、不造数、不清空最后成功缓存。
- 检查日志和落盘文件，确认无明文 DeepSeek Key、OAuth token、Cookie；账号删除/数据清除行为符合设计。
- 必须先由用户确认新运行预览再考虑编译/打包；本设计阶段不产出安装包。

## 9. 实施顺序建议（非实现计划审批）

设计稿确认后，下一阶段单独形成细化实现计划；建议计划先做不写生产功能的两个验证 Spike：

1. 用独立目录验证 Codex 双账号登录隔离和只读额度查询。
2. 验证 AGY 多账号支持情况；若支持，记录配置方法与账户隔离证据；若不支持，提交明确限制和不绕过原则。

两项通过或用户接受限制后，才进入 Python UI/Provider 分阶段实现。仍然每阶段提供可直接运行的 Python 预览，不编译打包。
